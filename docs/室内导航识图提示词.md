# 室内导航数据提取 — 识图任务

## 目标

从楼层平面图（图片）中提取结构化数据，生成 IndoorBuilding JSON，用于室内 Dijkstra 导航。

## 输出格式

输出一个完整的 MongoDB document JSON，结构如下：

```json
{
  "buildingId": "BUPT_ZHONGHE_ZONGHE",
  "buildingName": "综合实验教学楼",
  "campus": "北京邮电大学沙河校区",
  "floors": ["B1", "F1", "F2", "F3", "F4", "F5"],
  "floorPlans": {
    "B1": "base64_of_floor_image_B1",
    "F1": "base64_of_floor_image_F1",
    ...
  },
  "nodes": [
    {
      "id": "B1_ELEVATOR_LOBBY",
      "floor": "B1",
      "x": 200,
      "y": 300,
      "name": "B1电梯厅",
      "type": "LOBBY"
    }
  ],
  "edges": [
    {
      "from": "B1_ELEVATOR_LOBBY",
      "to": "B1_CORRIDOR_MAIN",
      "dist": 8.0,
      "floor": "B1"
    }
  ],
  "crossFloorEdges": [
    {
      "from": "B1_ELEVATOR_LOBBY",
      "to": "F1_ELEVATOR_LOBBY",
      "dist": 3.0,
      "type": "ELEVATOR"
    }
  ]
}
```

## 节点类型（type 字段）

| 值 | 说明 | 描述 |
|----|------|------|
| `ENTRANCE` | 建筑大门入口 | 每栋楼只有一个正门 |
| `LOBBY` | 大厅、电梯厅 | 每层至少一个 |
| `CORRIDOR` | 走廊拐点 | 连接各房间的路径节点 |
| `CLASSROOM` | 教室 | 普通教室 |
| `LAB` | 实验室 | 实验室/机房 |
| `OFFICE` | 办公室 | 教师办公室 |
| `TOILET` | 卫生间 | 男/女卫生间 |
| `ELEVATOR` | 电梯 | 垂直电梯位置 |
| `STAIRS` | 楼梯 | 步行楼梯位置 |

## 命名规则

### 节点 id 命名
`{楼层}_{类型}_{序号}`，例如：
- `F1_ENTRANCE`
- `F1_LOBBY`
- `F1_CORRIDOR_MAIN`（主走廊）
- `F1_CORRIDOR_A`（分支走廊）
- `F1_CLASSROOM_01`、`F1_CLASSROOM_02`
- `F1_TOILET`
- `F1_ELEVATOR_LOBBY`（电梯厅，连接电梯的节点）
- `F1_STAIRS`（楼梯节点）
- `B1_ELEVATOR_LOBBY`（地下层电梯厅）

### 跨层边命名
跨层边连接不同楼层的同名节点：
- 电梯：`F1_ELEVATOR_LOBBY` ↔ `F2_ELEVATOR_LOBBY` ↔ `F3_ELEVATOR_LOBBY` ...
- 楼梯：`F1_STAIRS` ↔ `F2_STAIRS` ↔ `F3_STAIRS` ...

## 提取规则

### 1. 每层必须包含的节点

| 节点 | 数量 | 说明 |
|------|------|------|
| `LOBBY` | ≥1 | 电梯厅/大厅 |
| `STAIRS` | ≥1 | 楼梯位置 |
| `CORRIDOR` | 若干 | 走廊网络，连接所有房间 |
| 房间节点 | 按实际 | 教室/实验室/办公室/卫生间等 |

**F1 层额外要求**：必须有 `ENTRANCE`（建筑正门入口）

### 2. 边（Edges）规则

- 相邻节点之间画边，距离单位 **米**
- 走廊节点必须前后串联形成路径网络
- 每个房间必须通过一条边连接到最近的走廊节点
- 距离按平面图比例尺估算；无比例尺时参考：
  - 房间门到走廊：2~3m
  - 走廊段长度：5~20m
  - 整层走廊总长：30~80m

### 3. 跨层边（CrossFloorEdges）规则

- 电梯连接上下层电梯厅，`type: "ELEVATOR"`，距离 3m/层
- 楼梯连接上下层楼梯节点，`type: "STAIRS"`，距离 4m/层
- B1 ↔ F1 ↔ F2 ↔ F3 ↔ F4 ↔ F5 逐层连接

### 4. 坐标系

- 使用平面图图片的像素坐标系
- x 向右为正，y 向下为正
- 节点坐标取房间门口位置或房间中心位置
- 走廊节点取走廊交叉口或拐角处

### 5. 每层节点数量建议

每层 **15~25 个节点**，包括：
- 5~8 个走廊节点（覆盖主要走廊网络）
- 8~12 个房间节点（教室/实验室/办公室等）
- 1~2 个卫生间
- 1 个电梯厅
- 1 个楼梯
- F1 额外加 1 个入口

## 需要识图的建筑

**北京邮电大学沙河校区 · 综合实验教学楼**（6 层）

| 楼层 | 说明 |
|------|------|
| B1 | 地下层 |
| F1 | 一层（有正门入口） |
| F2 | 二层 |
| F3 | 三层 |
| F4 | 四层 |
| F5 | 五层 |

## 输出要求

逐层识别，每层输出独立的 nodes 和 edges，最终合并为一个完整的 JSON。

每层的 `floorPlans` 中存入该层平面图的 base64 编码。
