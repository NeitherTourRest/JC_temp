> Spring Boot 4.0.6 · Java 21 · MySQL 8.0 + MongoDB 7

├── auth/        # JWT 认证

├── link/        # 旅游服务链接

├── shop/        # 餐馆
├── spot/        # 景点

## 一、AI 模块 `ai/`

### 1.1 配置 `config/`

**`AIConfig.java`**：通过 `@PostConstruct` 从 `ai-api-key.properties` 加载 DeepSeek/MiniMax/高德 API Key，不依赖 `@Value` 或 `application.yml`。

### 1.2 服务 `service/`

**`DeepSeekClient.java`**（185 行）：
- `chat(messages, systemPrompt)`：发送聊天请求，返回 AI 回复
- 工程设计：① 指数退避重试（最多 3 次）② 滑动窗口速率限制（10 次/分钟）③ Token 统计 ④ 60s 超时 ⑤ 错误分类（401/429/5xx）
- 对话截断：保留最近 10 条消息
- 优雅降级：AI 未配置时返回提示信息，不抛异常

**`AIChatService.java`**：
- `sendMessage(sessionId, userId, message)`：多轮对话，会话持久化到 MongoDB `ai_chat_sessions`
- `listSessions(userId)` / `getSession(sessionId)` / `deleteSession(userId, sessionId)`：会话管理

**`AIPlanService.java`**：
- `generatePlan(PlanRequest)`：天数+兴趣+预算+交通 → DeepSeek 生成 JSON 日程
- 8 层匹配：spot 名称→景点表 / food 名称→美食表 / Amap 地理编码→坐标 / Amap POI→餐馆
- `extractPlaceName()`：30+ 动词模式剥离活动名中的动词（"参观"、"游览"等）
- `computeDayRoutes()`：对每天的日程调用 Dijkstra 计算相邻点步行距离
- Changping 坐标验证过滤
- 请求级 Amap 缓存

**`AIBudgetService.java`**：
- `estimateBudget(BudgetRequest)`：生成分项预算报告（交通/门票/餐饮/住宿/其他）
- `estimatePerEvent(body)`：逐事件预算预测——读取行程中所有 slot 的景点/餐馆 → DeepSeek 对每个事件单独估价

**`DiaryGenerationService.java`**：
- `generate(prompt, itineraryId)`：选择已有行程或输入提示词 → DeepSeek 生成游记文本

**`DiarySummaryService.java`**：
- `summarizeDiary(diaryId)`：对已有日记生成 AI 摘要（日期/地点/摘要/亮点/建议）

**`MiniMaxClient.java`**：
- `generateImage(prompt, aspectRatio)`：图片生成 → 返回 URL
- `createVideo(prompt)` / `queryVideo(taskId)`：视频生成（异步，返回 taskId → 轮询查询）

## 二、认证模块 `auth/`

**`AuthController.java`**：
- `POST /auth/register`：注册（BCrypt 加密密码）
- `POST /auth/login`：登录 → 返回 accessToken(15min) + refreshToken(7d)
- `POST /auth/refresh`：刷新 Token（base64url 解码验证）

**`JwtAuthenticationFilter.java`**：
- 每次请求拦截 Bearer Token → 解析 JWT → 注入 SecurityContext
- JWT 使用 base64url 编码（非标准 base64）

**`JwtUtil.java`**：
- `generateAccessToken(username)` / `generateRefreshToken(username)`
- `validateToken(token)` / `getUsernameFromToken(token)`

## 十一、导航算法模块 `navigation/`

### 11.1 图数据结构 `graph/`

**`Graph.java`（~120 行）**：
- `adjacencyMap: Map<String, List<GraphEdge>>`：邻接表
- `getEdges(nodeId)` / `addNode()` / `addEdge()`
- `findNearestNode(lat, lng)`：网格空间索引（9 格 cell），2000 倍加速
- `isSameComponent(id1, id2)`：判断两节点是否在同一连通分量
- `computeComponents()`：BFS 计算连通分量
- `buildGridIndex()`：构建网格索引
- 反转边自动添加（双向图）

**`GraphNode.java`**：`nodeId`, `latitude`, `longitude`, `name`, `distance`（Dijkstra 临时值）, `previous`, `visited`, `componentId`

**`GraphEdge.java`**：`edgeId`, `fromNodeId`, `toNodeId`, `distance`, `roadType`（motorway/trunk/primary/secondary/tertiary/residential/service/footway/cycleway/path/steps）, `name`, `isOneWay`, `maxSpeed`, `congestionLevel`
- `getWeight(strategy, transportSpeedKmh)`：DISTANCE 策略返回距离，TIME 策略返回时间
- `getEffectiveSpeed(maxSpeedCap)`：道路基速 × 拥挤系数，cap 交通上限
- `isAllowedForTransport(transport)`：按交通方式过滤道路类型

### 11.2 算法 `algorithm/`

所有算法全部自实现，非外部库调用。

| 算法 | 文件 | 复杂度 | 功能 |
|------|------|--------|------|
| **Dijkstra** | `DijkstraAlgorithm.java` | O((V+E)logV) | 最短路径 + 全距计算（computeAllDistances） |
| **TSP** | `TSPAlgorithm.java` | O(n²) 贪心 + O(n²) 每轮 2-opt | 多目标最优路线 |
| **TopKSorter** | `TopKSorter.java` | O(N logK) 空间 O(K) | Top-K 选择（自实现 MinHeap） |
| **FuzzyMatcher** | `FuzzyMatcher.java` | 编辑距离 O(m·n) / Trie O(L) | Levenshtein + Trie 前缀树 |

### 11.3 服务

**`NavigationService.java`**（283 行）：
- `planRoute(RouteRequest)`：路径规划入口，单目标→Dijkstra，多目标→TSP
- 多交通方式：TIME 策略下每种交通单独跑 Dijkstra，选最快
- 连通分量桥接：不同子图间找最近节点对 → 插入步行过渡段
- 返回含分段路径的 RouteResponse（segments[] 含 transport、roadType、distance）

**`POISearchService.java`**：
- 加载 `pois.json`（6,167 条 OSM 地名）
- 子串匹配搜索

### 11.4 实体与仓储（MySQL）

**`RoadNode.java`**：`nodeId`, `latitude`, `longitude`

**`RoadEdge.java`**：`id`, `edgeId`, `fromNodeId`, `toNodeId`, `distance`, `roadType`, `name`, `isOneWay`, `maxSpeed`, `congestionLevel`

### 11.5 控制器

| 端点 | 方法 | 说明 |

| `/navigation/poi/search` | GET | POI 搜索 |

## 十二、推荐引擎 `recommend/`

**`SpotRecommendationEngine.java`**（383 行）：多信号加权融合推荐。

**信号体系**：

| 信号 | 权重 | 来源 |
|------|------|------|
| 用户兴趣标签匹配 | 32% | `UserPreference.interestCategories` → 类别映射 |
| 景点热度（对数归一化） | 22% | `Spot.popularity` 取 log |
| 景点评分（置信度加权） | 18% | `Spot.avgRating × min(1, ratingCount/50)` |
| 收藏类别亲和 | 10% | 用户收藏过的景点的类别统计 |
| 浏览类别亲和 | 8% | 用户浏览过的景点的类别统计 |
| 旅游优先级 | 5% | 景点/景区/公园/博物馆/休闲类加成 |

**多样性重排**：Top(K×3) → 每类最多 2-3 个。

**群组推荐**：多用户兴趣取交集优先，并集兜底。
