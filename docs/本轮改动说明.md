# 本轮改动说明

## 1. 改动目标

本轮改动主要完成了两件事：

1. 收敛并增强推荐算法，使首页推荐真正体现用户偏好变化。
2. 新增“景点详情 -> 导航页”的通用跳转导航能力，支持浏览器获取当前位置并自动开始路线规划。

设计原则：

- 尽量不打乱现有模块边界
- 优先复用现有接口
- 保持原有景点列表、景区内导航、AI、行程等功能不受影响

---

## 2. 推荐算法改动

### 2.1 统一推荐内核

新增统一推荐引擎：

- [SpotRecommendationEngine.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/recommend/SpotRecommendationEngine.java:24)

作用：

- 单人推荐统一走 `recommendForUser`
- 多人协同推荐统一走 `recommendForGroup`
- 使用 `TopKSorter` 做 Top-K 选取
- 统一候选过滤、打分、理由生成、多样性重排

### 2.2 接入的后端模块

以下模块已改为复用统一推荐引擎：

- [RecommendService.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/recommend/RecommendService.java:47)
- [SpotService.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/spot/service/SpotService.java:85)

这意味着：

- 首页综合推荐
- `/spots/recommend`
- `/collaboration/recommend`

三处景点推荐逻辑已经统一，不再各写一套规则。

### 2.3 兴趣偏好映射

为解决“个人偏好标签”和“景点真实分类”不一致的问题，在推荐引擎中加入了兴趣映射：

- `自然风光 -> 景点 / 景区 / 公园 / 休闲`
- `历史古迹 -> 景点 / 景区 / 博物馆`
- `主题乐园 -> 景点 / 休闲`
- `博物馆 -> 博物馆`
- `校园 -> 校园`
- `美食 -> 商场 / 休闲`

位置：

- [SpotRecommendationEngine.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/recommend/SpotRecommendationEngine.java:34)

### 2.4 权重调整

为了让“修改偏好后首页推荐顺序变化更明显”，单人推荐权重做了进一步调整：

- `interestMatch`: `0.18 -> 0.32`
- `popularity`: `0.32 -> 0.22`
- `rating`: `0.22 -> 0.18`

位置：

- [SpotRecommendationEngine.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/recommend/SpotRecommendationEngine.java:215)

调整后的效果：

- 兴趣命中时，排序变化会更明显
- 高热度景点不再完全压制个性化结果
- 更适合验收时展示“动态推荐”

### 2.5 推荐理由输出

首页推荐结果现在支持返回推荐理由 `reason`，例如：

- `匹配你的兴趣`
- `评分较高`
- `近期热门`

位置：

- [RecommendService.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/recommend/RecommendService.java:84)

## 3. 首页推荐联动改动

### 3.1 首页改为使用推荐接口

首页已不再直接读取普通景点列表，而是优先调用：

- `GET /api/v1/recommend`

位置：

- [HomeView.vue](/Users/reiayanami/Project/JC_temp/frontend/src/views/home/HomeView.vue:127)
- [frontend/src/api/recommendApi.ts](/Users/reiayanami/Project/JC_temp/frontend/src/api/recommendApi.ts:4)

逻辑：

- 有推荐结果时使用推荐结果
- 推荐接口失败或为空时，回退到普通景点列表

### 3.2 登录态用户标识修复

为避免首页推荐拿不到真实用户 ID，修复了前端登录态本地存储：

- 保存 `userId`
- 保存 `username`
- 页面刷新后能恢复真实用户身份

位置：

- [authStore.ts](/Users/reiayanami/Project/JC_temp/frontend/src/stores/authStore.ts:11)
- [ProfileView.vue](/Users/reiayanami/Project/JC_temp/frontend/src/views/profile/ProfileView.vue:241)

这样首页在切换账号后，重新进入首页时能够按真实账号请求推荐。

### 3.3 推荐接口公共读取

为了保证首页未登录时也能访问推荐接口，安全配置增加了：

- `GET /api/v1/recommend/**` 允许匿名访问

位置：

- [SecurityConfig.java](/Users/reiayanami/Project/JC_temp/JC/src/main/java/com/journeycraft/jc/common/config/SecurityConfig.java:38)

## 4. 景点详情跳转导航改动

### 4.1 功能目标

支持从景点详情页直接进入导航页，并完成：

1. 自动带入当前景点作为终点
2. 调用浏览器定位获取当前位置作为起点
3. 自动发起路径规划
4. 定位失败时退化为手动选起点

### 4.2 为什么这是“通用设置”

这个能力不依赖景点分类，也不依赖景点是否有内部设施，仅依赖：

- 景点存在经纬度

因此以后景点数据扩展或更换，只要保留经纬度字段，该功能仍然可用。

### 4.3 景点详情页改动

景点详情页新增：

- `🧭 前往导航页`

位置：

- [SpotDetailView.vue](/Users/reiayanami/Project/JC_temp/frontend/src/views/spot/SpotDetailView.vue:70)

按钮行为：

- 将 `targetLat`
- `targetLng`
- `targetName`

通过路由 query 传递到 `/navigation`

实现位置：

- [SpotDetailView.vue](/Users/reiayanami/Project/JC_temp/frontend/src/views/spot/SpotDetailView.vue:376)

### 4.4 导航页改动

导航页新增“外部目标注入”逻辑：

- 解析 query 中的景点目标点
- 自动将目标点设为终点
- 使用浏览器 `navigator.geolocation` 获取当前位置
- 如果高德对象可用，优先做 GPS -> 地图坐标转换
- 成功后自动调用原有导航接口规划路线
- 失败则提示用户手动选起点

位置：

- [NavigationView.vue](/Users/reiayanami/Project/JC_temp/frontend/src/views/navigation/NavigationView.vue:469)

### 4.5 接口影响

这一部分**没有新增后端接口**，完全复用了已有接口：

- `POST /navigation/route`

因此：

- 不需要新增 Controller
- 不需要改动后端路由
- 不影响其他使用导航接口的页面

## 5. 哪些页面会体现排序变化

### 会变化

- 首页推荐区

原因：

- 首页走 `/recommend`
- `/recommend` 已接入统一推荐算法

### 不会变化

- 景点列表页 `/spots`

原因：

- 当前仍走 `spotApi.search(...)`
- 默认按 `popularity` 排序
- 不是个性化推荐入口

因此验收时如果要展示“改偏好 -> 排序变化”，应该优先展示首页，而不是景点列表页。

## 7. 当前仍存在的限制

### 7.1 首页推荐刷新时机

当前首页推荐仍然主要依赖页面重新进入或重新加载。  
如果希望“保存偏好后立刻看到首页变化”，还可以进一步做：

- 偏好保存成功后主动跳回首页并刷新推荐
- 或使用全局事件/状态刷新首页推荐数据

### 7.2 景点列表页仍是普通列表

如果后续需要让“景点页本身”也展示个性化顺序，需要单独增加：

- 个性化推荐 Tab
- 或“为你推荐”模式

不建议直接替换现有搜索列表逻辑，否则会影响检索场景。

## 9. 验收演示建议

建议按下面顺序演示：

1. 使用账号 A 登录首页，展示当前推荐顺序
2. 修改账号 A 偏好，返回首页后展示推荐变化
3. 切换到账号 B，展示首页推荐再次变化
4. 打开某个景点详情页，点击 `前往导航页`
5. 浏览器允许定位后，展示“当前位置 -> 目标景点”的自动规划结果

这样可以同时证明：

- 推荐算法是动态的
- 推荐结果与用户偏好相关
- 景点与导航模块已经形成业务联动
- 改动没有破坏原有页面主流程
