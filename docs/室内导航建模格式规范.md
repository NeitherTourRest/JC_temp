# 室内导航建模格式规范

## 1. 任务概述

你需要根据综合实验教学楼的6层平面图（B1、F1~F5），提取每层的房间/区域位置、走廊网络、楼梯/电梯位置，并构建一个完整的导航图（Graph）。最终产出 **一份 JSON 文档** 入库到 MongoDB `JourneyCraft.indoor_navigation` 集合中。

---

## 2. 后端数据模型（Java → MongoDB）

### 顶层文档 `IndoorBuilding`

存储一个楼宇的全部导航信息，对应 MongoDB 集合 `indoor_navigation`。

```json
{
  "buildingId": "BUPT_ZHONGHE_ZONGHE",
  "buildingName": "综合实验教学楼",
  "campus": "北京邮电大学沙河校区",
  "floors": ["B1", "F1", "F2", "F3", "F4", "F5"],
  "floorPlans": {
    "B1": "/images/indoor/BUPT_ZHONGHE_ZONGHE/B1.jpg",
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `buildingId` | string | 楼宇唯一标识（与地图POI关联） |
| `buildingName` | string | 楼宇显示名称 |
| `campus` | string | 校区名称 |
| `floors` | string[] | 所有楼层列表，格式：`B1`=地下一层, `F1`=一层, `F2`=二层... |
| `floorPlans` | object | 楼层平面图URL映射 `{楼层: 图片URL}` |
| `nodes` | Node[] | 导航节点列表 |
| `edges` | Edge[] | 同层走廊边列表 |
| `crossFloorEdges` | CrossFloorEdge[] | 跨层连接边列表 |

## 3. Node（节点）

导航图中的每个**关键点**，包括：房间门口、走廊拐角、楼梯口、电梯口、大厅中心、建筑出入口。

```json
{
  "id": "F1_ROOM101",       // 唯一ID，命名规范：{楼层}_{英文描述}(_编号)
  "floor": "F1",            // 楼层：B1 / F1 / F2 / F3 ...
  "x": 100,                 // 节点在该楼层平面图上的X坐标(像素)
  "y": 150,                 // 节点在该楼层平面图上的Y坐标(像素)
  "name": "101教室",         // 显示名称
  "type": "CLASSROOM"       // 节点类型
}
```

### 节点类型枚举

| type | 用途 | 图标 |
|------|------|------|
| `ENTRANCE` | 建筑出入口 | 🚪 |
| `CLASSROOM` | 教室 | 📚 |
| `LAB` | 实验室 | 🔬 |
| `OFFICE` | 办公室 | 📋 |
| `TOILET` | 卫生间 | 🚻 |
| `ELEVATOR` | 电梯（跨层节点） | 🛗 |
| `STAIRS` | 楼梯（跨层节点） | 🪜 |
| `LOBBY` | 大厅/门厅 | 🏛 |
| `CORRIDOR` | 走廊中间节点 | ➡️ |

### 节点ID命名规范

```
{楼层}_{英文关键词}_{序号}
```

示例：
- `F1_ENTRANCE` — 一楼大门
- `F1_HALL_A` — 一楼大厅A点
- `F1_CORRIDOR_1` — 一楼走廊节点1
- `F1_ROOM101` — 101教室
- `F1_TOILET_W` — 一楼西卫生间
- `F1_STAIRS_N` — 一楼北楼梯
- `F2_STAIRS_N` — 二楼北楼梯（与F1_S TAIRS_N组成跨层边）
- `F1_ELEVATOR` — 一楼电梯
- `F2_ELEVATOR` — 二楼电梯（与F1_ELEVATOR组成跨层边）

---

## 4. Edge（同层走廊边）

连接**同一楼层**两个可达节点之间的路径。

```json
{
  "from": "F1_ENTRANCE",   // 起点节点ID
  "to": "F1_HALL_A",       // 终点节点ID
  "dist": 8.0,             // 实际距离(米)
  "floor": "F1"            // 楼层
}
```

**规则：**
- 走廊沿中轴线建模，拐弯处必须有 `CORRIDOR` 类型的节点
- `dist` 必须根据平面图比例尺换算为**实际米数**
- 不可斜穿房间，必须沿着走廊走
- 每个房间至少有一个边连接到最近走廊的节点

---

## 5. CrossFloorEdge（跨层连接边）

连接**不同楼层**之间的楼梯或电梯。

```json
{
  "from": "F1_STAIRS_N",   // 本层楼梯口节点ID
  "to": "F2_STAIRS_N",     // 上层对应楼梯口节点ID
  "type": "STAIRS",        // 类型：STAIRS / ELEVATOR
  "dist": 5.0              // 跨层转换距离(米)
}
```

**规则：**
- 每部楼梯/电梯在**每层**都有一个对应节点，命名相同前缀
- `from` 和 `to` 的节点类型必须与 `type` 一致（STAIRS→STAIRS，ELEVATOR→ELEVATOR）
- 楼梯距离通常按 5m 估算，电梯按 3m 估算

---

## 6. 从平面图提取数据的步骤

### Step 1: 分析每张平面图

对 B1.jpg / F1.jpg / F2.jpg / F3.jpg / F4.jpg / F5.jpg 逐张分析：

```
对于每张平面图：
1. 确定比例尺：寻找图上的比例尺标记，如果找不到，按以下默认值估算：
   - 教室门宽约 1.2m 对应约 24px → 比例约 1px = 0.05m
   - 走廊宽约 3m 对应约 60px
   
2. 识别房间区域及其类型：
   - 较大的矩形区域 → 教室 (CLASSROOM) / 实验室 (LAB)
   - 小型矩形 → 办公室 (OFFICE)
   - 有"卫"标记 → 卫生间 (TOILET)
   - 大厅/空旷区域 → LOBBY
   - 有楼梯符号 → STAIRS
   - 有电梯符号 → ELEVATOR
   - 建筑正门 → ENTRANCE

3. 标记房间门口位置（每个房间至少一个门口节点）

4. 标记走廊中轴线拐点：
   - 走廊每隔一段距离设置 CORRIDOR 节点
   - 走廊拐弯处必须有节点

5. 标记楼梯/电梯在每层的位置
```

### Step 2: 构建导航图

```
1. 把所有节点（房间门口+走廊节点+跨层节点）放在同一个图的 nodes[] 中

2. 连接走廊节点形成走廊骨架：
   - 走廊直线段：相邻两个 CORRIDOR 节点相连
   - 走廊拐弯：CORRIDOR 节点间相连

3. 把房间门口节点连接到最近的走廊节点

4. 为每部楼梯/电梯创建跨层边：
   - F1_STAIRS_N → F2_STAIRS_N
   - F1_ELEVATOR → F2_ELEVATOR
   - (以此类推到所有楼层)

5. 根据比例尺计算每条边的实际距离(米)
```

### Step 3: 验证

```
1. 任意两层之间是否都有可达路径（通过楼梯/电梯）
2. 每个房间是否有至少一个入口节点
3. 走廊网络是否连通
4. 距离是否合理（米的量级）
```

## 7. 输出格式要求

最终输出一个完整的 JSON 对象，直接对应 MongoDB 文档。

### 输出检查清单

- [ ] `buildingId` 正确：`BUPT_ZHONGHE_ZONGHE`
- [ ] `floors` 包含所有6层：`["B1", "F1", "F2", "F3", "F4", "F5"]`
- [ ] 每层至少有 1 个 `ENTRANCE` 节点（F1）或楼梯/电梯连接
- [ ] 所有 `edges` 的 `from`/`to` 都在 `nodes` 中存在
- [ ] 所有 `crossFloorEdges` 的 `from`/`to` 都在 `nodes` 中存在
- [ ] 跨层边连接了上下对应的楼层
- [ ] 没有孤儿节点（每个节点至少有一条边）
- [ ] 走廊网络连通：从任一节点可到达同层其他节点
- [ ] 距离为正数，单位米

## 8. 提交方式

建模完成后，将最终的 JSON 文档通过以下 Python 脚本写入 MongoDB：

```python
import pymongo, json

client = pymongo.MongoClient('mongodb://localhost:27017/')
db = client['JourneyCraft']
collection = db['indoor_navigation']

# 先清除旧数据（如果存在）
collection.delete_many({"buildingId": "BUPT_ZHONGHE_ZONGHE"})

# 用你的最终 JSON 替换下面这行
with open('indoor_building.json', 'r', encoding='utf-8') as f:
    data = json.load(f)

collection.insert_one(data)
print("写入成功")
```

> ⚠️ 注意：这是**一个文档包含全部楼层**的格式（single-document），而非之前每层一个文档的格式。之前的旧数据需要用 `buildingId = "BUPT_SHAHE_ZONGHE"` 清理掉，以保证只有这一个新文档。

## 10. 错误排查指南

| 问题 | 原因 | 解决 |
|------|------|------|
| API返回 "Building not found" | MongoDB中buildingId不匹配 | 确认 JSON 中 `buildingId` 字段值一致 |
| API返回 "No path found" | 起点/终点节点没有连通 | 检查 `edges` 和 `crossFloorEdges` 是否完整 |
| 前端路径画错位置 | 节点 `x`/`y` 坐标与图片像素不对应 | 坐标单位是平面图图片的像素坐标 |
| 前端无节点可选项 | `nodes` 列表为空或API未返回 | 确认 JSON 写入成功 |
| Spring Boot启动失败: ConflictingBeanDefinitionException | 存在多个 `MongoConfig` | 删除多余的 `MongoConfig.java` |
